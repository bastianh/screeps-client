What is this?

A from-scratch reimplementation of the Screeps game client. The UI is built with SolidJS, rooms and the world map are rendered with PixiJS (WebGL), and all server communication goes through screeps-connectivity, a zero-dependency TypeScript library. It connects to the official screeps.com servers (World and Season), classic private servers, and xxscreeps — and adapts its UI to each server's advertised capabilities.

This page focuses on what the client adds compared to the official client; the parity section summarizes the familiar features it reimplements.

Run it anywhere

The official client is tied to screeps.com and the Steam app. This client is packaged so it can be served, embedded, or installed wherever your server lives.

Quick start — play on the official servers

npx screeps-client-proxy

This is the recommended way to use the client with screeps.com (World and Season) or any other server you don't control. It starts a small local proxy that serves the client at http://localhost:8080/ with a server-list login and forwards API + WebSocket traffic to whichever backend you pick — sidestepping browser CORS entirely. One instance handles any number of servers. #212, #247

Embedded in private servers

screepsmod-client-new serves the client directly from any classic Screeps server at /client — no separate hosting, and the server seeds the page with its own version info for an instantly configured login.

xxscreeps support

xxscreeps-mod-client wires the client into xxscreeps. The login screen adapts to the server's .screepsrc.yaml — guest access, e-mail registration, and Steam login buttons appear only when the backend actually offers them.

#175, #191

Desktop app

A lightweight Tauri v2 desktop app for macOS, Windows, and Linux with a server-list login screen. Credentials are stored in the OS keychain (macOS Keychain, Windows Credential Manager, Linux Secret Service), and native HTTP makes every server reachable without CORS tricks.

⚠️ The pre-built desktop binaries are released manually and are currently out of date most of the time. For an up-to-date client, prefer npx screeps-client-proxy above.

Guest & spectator mode

On servers that allow it, the client connects as a read-only guest without any login — straight onto the world map, with the server's message of the day shown as a dismissable overlay. Build/flag tools and the code editor are hidden for guests.

Mobile & touch

Room and map views support two-finger pinch-to-zoom with simultaneous panning, and the renderer includes fixes specifically for mobile browsers — the client is usable from a phone or tablet.

#33, #27

Flexible login & per-server capabilities

Steam, Discord, e-mail/password, and API-token login are all supported, including the username-selection flow for brand-new OAuth signups. A unified capabilities layer reads each server's /api/version and shows only what the server supports — market, messaging, room history, decorations, server-password fields, and login providers all gate themselves automatically. Session handling understands both static API tokens and the rotating tokens used by screepsmod-auth.

#180, #176, #178, #182

Custom UI panels unique

Your bot can define its own UI. A JSON document in a memory segment describes buttons, dropdowns, status lines, and collapsible headers, and the client renders them in the map and room sidebars. Clicking an element calls a handler function in your bot code through the console API — with the current view context (shard, selected room, selected objects, marked tile) — and the bot's reply is turned into toasts, room navigation, console-input insertion, or a config reload. Elements can be conditional on selection type or room standing, carry confirmation prompts, and per-object action menus appear in the selection panel.

A visual editor in the settings (structured form and raw-JSON CodeMirror mode, with live validation) makes building these panels comfortable without hand-writing the segment.

Developer tools

TypeScript in the code editor unique

Write your Screeps modules in TypeScript with full in-browser IntelliSense — completion, hover type info, and inline diagnostics for the Screeps API, powered by a TypeScript language service in a Web Worker. Branches can mix .ts and .js modules, conversion works both ways, and on save the TS transpiles to JS for the server while the original source is kept alongside it.

In-client history playback

Scrub through a room's past on servers that store tick history: a timeline slider spanning up to 200,000 ticks, ±10/±100 stepping, playback speeds from 0.5 to 20 ticks/second, and estimated real-world timestamps — without leaving the client.

In-room decoration editor

Room decorations render fully (wall graffiti, floor/wall textures, badges) — and are edited in place: drag, resize, and rotate a decoration over the live, ticking room, with the artwork previewed wall-masked and tinted exactly as it will look.

A "smooth animations" toggle that snaps tick animations for a lower-distraction view, context-sensitive mode hints (build/flag/move) with right-click to exit any mode, double-click to enter a room from the map, and configurable creep-name and room-visual toggles.

Feature parity with the official client

Beyond the extensions above, the client reimplements the day-to-day features you expect, matched against the official client's behaviour and rendering.

  • Full room rendering: every structure with its vanilla look and animations — tower aim and action beams, lab reactions and cooldown glows, spawn progress ring and energy fill, resource-typed store fills, terminal send pulse, extractor spin, power spawn meter, power banks, portals, keeper lairs, invader/Source Keeper gems, tombstones, ruins (#117, #132, #125, #252, …)
  • Creeps with player badges, tick-synced interpolated movement, and say bubbles (#74)
  • RoomVisuals and disabled-structure marking, crisp at every zoom (#94, #236)
  • Flags (create, move across rooms, colors) and construction with build panel (#50)
  • Market: order books per resource, price history, my orders, credit ledger — read-only, with the target room pre-filled from the room you came from (#143, #197)
  • World and power leaderboards with season browsing and rank search (#232)
  • Account overview and public player profiles with GCL/GPL rings, stat tiles, and owned-room minimaps (#138, #160, #194)
  • In-game messaging with conversation deep links (/messages/<user>) (#162, #195)
  • Power creep management: create, upgrade, rename, delete (#140)
  • Per-room overview page with stat tiles and history graph (#199)
  • Badge editor with designs, colours, variations, and auto-onboarding for new players (#41, #51)
  • Notification preferences, respawn flow with world-status polling, and password management from the user menu (#158, #131, #129)

Known gaps: there is no simulation room or tutorial, and market orders are created and cancelled through the in-game API rather than the UI.

Performance

The renderer was built for large worlds and long sessions.

  • Map terrain is baked in a Web Worker and cached as WebP tiles via the Cache API, per shard, room, and zoom level — panning and reloads reuse tiles instead of re-rendering (#5, #102)
  • Room terrain renders once into a GPU texture; walls and ramparts redraw only when they actually change (#28, #121)
  • Night-time light pools follow moving creeps through a GPU lightmap driven by the renderer's own interpolation loop (#105)
  • Sprite pooling on the map, batched terrain geometry, and per-frame allocation trimming in hot paths (#8, #27)
  • Aggressive code splitting: the editor, map, and CodeMirror load lazily, keeping the initial download small (#16, #242)
